# MIDI Controller — 把 MIDI 键盘变成你的 TourBox / 生产力宏控制器

[![Platform](https://img.shields.io/badge/platform-Windows%2010%2F11-0078D6)](#)
[![Python](https://img.shields.io/badge/python-3.12%2B-3776AB)](#)
[![License: MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)

百元级的 MIDI 键盘（如 M-VAVE SMK-25、Akai MPK Mini、Arturia MiniLab 等）拥有大量**物理旋钮、打击垫、推子、弯音轮与琴键**，硬件素质远超同价位单手键盘，却往往在桌面吃灰。  
而专业修图/剪辑控制台（如 TourBox）售价上千元，老牌 MIDI 映射软件 **Bome MIDI Translator Pro** 不仅价格昂贵，配置逻辑对非专业用户也较为繁琐。

**MIDI Controller** 是 Windows MIDI 生产力控制转换器。它将本页列出的 MIDI 消息转换为**键盘快捷键、鼠标操作、旋钮步进、系统音量调节与宏序列**，并支持**根据当前前台软件自动切换配置**。

---

## 核心特性

- **🎛️ TourBox 式旋钮深度优化**
  - **旋钮步进按键**：左转 / 右转分别触发不同快捷键（如 `[` / `]` 调画笔、方向键逐帧移动）。
  - **修饰键 + 滚轮**：旋转即发送带修饰键的垂直/水平滚轮（如 `Ctrl + 滚轮` 缩放画布、`Alt + 滚轮` 缩放时间轴）。
  - **修饰键 + 按住拖动**：旋转时按住修饰键与鼠标键并移动光标，停手超过设定阈值（如 400ms）后自动松开，可配置为 `Alt + 右键拖动` 等操作。
  - **动态速度感应（加速）**：转得越快步进倍率越高（最高 8×），兼顾慢拧微调与快拧大幅跨越。
  - **明确编码选择**：支持绝对值、旧 Two's Complement/Binary Offset 单步模式，以及保留报文步数的 Sign magnitude、Binary offset、Arturia relative 3。可反转方向；不自动猜测编码，不承诺兼容所有厂商协议。

- **👆 多维触发与手势识别**
  - 支持 **Note**、**7bit/14bit CC**、**Pitch Bend**、**Program Change**、**Aftertouch/Polytouch** 及 **RPN/NRPN 传输事件**；支持指定来源或任意来源。
  - 同一键盘配置可同时接收多个输入端口；各来源、通道、控件的历史、解码、手势及按住资源隔离，仍只使用一个输出端口。
  - 完整弯音保留 `-8192..8191`；旧映射的 `-64..64` 数值、条件和动作保持兼容。
  - CC按钮/踏板可设置阈值和反向，新映射按跨阈值边沿触发，数值变化仍逐条处理。
  - 同一物理按键/打击垫可同时绑定 **普通（立即）**、**短按**、**长按（阈值可调）**、**双击（300ms）** 四种手势，互不干扰。
  - 支持 **数值区间过滤**（如推子推到 `100–127` 高位区间才触发某动作）。

- **🔀 变量系统、条件表达式与 Shift 层**
  - 内置运行时变量引擎（支持赋值 `=`、累加 `+=` 含上下限与循环 Wrap、布尔切换 `Toggle`、直接读取输入力度/数值 `from_value`）。
  - 支持多条件组合判断：`shift==1, mode!=2, $value>64, $number==60`。
  - 配合 **“命中后停止后续映射”** 开关，可轻松构建多套 **Shift 组合层** 或 **旋钮多模式复用**（一个旋钮通过按键切换功能：模式 0 调音量、模式 1 刷时间轴、模式 2 调画笔）。

- **🪟 前台进程感知与自动切换**
  - 后台低开销监控当前活动窗口进程（如 `photoshop.exe`、`resolve.exe`、`premiere.exe`、`chrome.exe`）。
  - 切换软件即自动切入对应配置集，并自动释放上一配置按住的修饰键防止卡键；当前配置未定义的按键自动回退（Fallback）到 **“全局”** 配置。

- **⚡ 底层硬件扫描码输入与丰富动作库**
  - 基于 Windows `SendInput` + **硬件扫描码（Scan Code）** 注入键盘与鼠标事件，兼容绝大多数修图/剪辑软件与游戏。
  - 支持 **点按**、**跟随按住（按下与松开与琴键/打击垫完全同步）**、**按住连发（Repeat）**、**宏动作序列（多步动作 + 独立毫秒级延迟）**。
  - 支持 **系统主音量跟随推子/旋钮**（基于 `pycaw` 实时线性控制或步进/静音）、多媒体控制、启动程序、打开网址、静默执行命令行、以及 **MIDI 信号回传/转发**。

- **💬 鼠标旁 HUD 轻提示 & 实时监视器**
  - 可按条开启鼠标旁半透明穿透式 HUD，转动旋钮或切换模式时即时浮现当前功能名称、数值与变量状态，不抢焦点。
  - MIDI 监视器显示来源，最多500行，连续控件合并刷新。“原始诊断”限速显示后端原始消息；未支持类型仅诊断，不执行或学习。不录制或回放消息。
  - **学习**记录来源、类型、通道与编号；学习14bit CC/RPN/NRPN前先选择对应类型，避免被组成它的原始CC抢先捕获。旋钮编码手动确认。
  - 支持最小化驻留系统托盘，随时一键暂停/恢复映射。
  - **独立键盘配置**：新建、复制整套应用映射并重新绑定设备，一次启用一份配置；按精确端口名称重连。部分输入断线只取消该来源的工作，其他输入继续；切换、暂停和退出清理整个会话。

## 快速开始

### 方式一：从源码运行（推荐开发者）

环境要求：**Windows 10 / 11**，**Python 3.12+**。

```powershell
# 1. 安装依赖
pip install -r requirements.txt

# 2. 启动程序（带控制台，便于查看日志）
python main.py

# 或使用启动脚本：
.\run.ps1          # 普通无控制台后台启动
.\run.ps1 -Admin   # 以管理员权限启动（当目标软件以管理员运行时需要）
.\run.ps1 -Test    # 运行离线单元测试；测试入口阻止真实键鼠、MIDI 等输出
```

### 方式二：打包为独立 EXE

无需目标机器安装 Python，可一键打包为免安装绿色目录：

```powershell
pip install -r requirements-build.txt
.\build.ps1
```

打包完成后生成于 `dist\MIDIController\MIDIController.exe`。分发或移动时请携带整个 `MIDIController` 文件夹（含 `_internal` 目录）。程序配置保存在同目录的 `config.json` 中，重新打包会自动保留已有配置。

## 3 分钟上手指南

1. **连接设备**：选择或新建“键盘配置”，在输入列表勾选一个或多个端口；需要 MIDI 输出动作时选择唯一输出端口。
2. **学习控件**：新建映射后点击“学习”，操作控件即可记录来源、类型、通道和编号。14bit CC/RPN/NRPN先选类型再学习；需要跨输入复用时将来源改为“任意来源”。
3. **绑定动作**：在下方动作区选择想要执行的操作（如 `键盘按键`、`鼠标滚轮`、`修饰键+拖动` 等），点击保存即可立即生效。
4. **绑定专属软件**：在左侧点击 **“新建配置”**，填入进程名（弹窗会自动提示你刚才切过来的前台进程名，如 `chrome.exe`），即可为该软件建立专属键位。

## 多把键盘分别使用

- **新建键盘**创建空白映射与空端口；**复制键盘**深拷贝映射及输入/输出绑定。复制不会猜测或改写映射中的来源名称，换设备后请重新勾选端口并学习/修改指定来源及编号。
- 上方键盘配置与左侧应用配置分工不同：每把键盘各自拥有“全局”和软件专属映射；前台自动切换及未命中时回退全局的行为保持不变。启用映射、按前台切换和托盘选项仍为全局开关。
- 每次启用一份键盘配置，其中多个输入可同时接收。拔掉某个输入后约每秒按原名重试，健康端口不重复打开；不会自动选名称相似的端口。取消某端口勾选即停止其重连，全部取消即无输入。
- 通道触后没有音符编号，复音触后保留编号；压力0仍是连续数值，不作为松键或按键手势。
- 只接收系统可见 MIDI 1.0 端口。系统已暴露的蓝牙端口可按普通端口选择，本程序不自建BLE连接或原生MIDI 2。SysEx/厂商灯屏/电动推子反馈未实现，MIDI输出仅有现有Note/CC/Program动作。

### 精度、踏板与相对编码

- 弯音“数值模式”可选旧 `-64..64` 或完整 `-8192..8191`；新建映射默认完整精度，旧配置迁移保持旧模式。范围、`$value`、变量读取、HUD与动作使用该映射的数值视图。音量/鼠标跟随按其真实范围归一化；14bit/完整弯音转发到7bit MIDI数值时缩放至0..127。
- CC踏板默认阈值64，高于或等于阈值表示按下；极性反向将其翻转。新映射使用“边沿”：首次高态允许按下，首次低态不制造松开；持续高值不重复按下。旧映射迁移保留“旧兼容/逐条”行为，可手动改为边沿来修正重复触发。`change` 不做全局去重，到顶/到底的绝对旋钮仍可连续操作。
- 阈值与极性同时作用于匹配、手势和按住释放；条件或范围不再满足时释放已拥有的跟随按住资源。编辑、停用或删除映射会清理既有动作。显式“仅按下”由相应“仅松开”或断线/会话清理结束。
- 旧 `rel_2c`：0/64中性，1..63增加，65..127减少；旧 `rel_64`：64中性、两侧反向。两者默认仍每报文单步，可勾选“旧相对模式也保留报文步数”。
- 新 `rel_signed`：1=+1、65=-1、0/64中性；新 `rel_offset`：步数=value-64（包括0=-64）；新 `rel_arturia3`：仅13..19为value-16，16和额外兼容值0中性，其他值忽略。选“反转旋钮方向”可翻转。保留步数时不再叠乘时间加速；旧单步/绝对模式继续使用原加速行为。

### 14bit CC 与参数消息

- 14bit CC编号0..31：MSB为CC n，LSB为CC n+32，组合值 `(MSB<<7)|LSB`。每条MSB清掉旧LSB并立即发粗值，随后LSB发细调；首次孤立LSB不发事件，后来的MSB将其清零。这是本应用明确采用的拼装策略。
- RPN使用101/100、NRPN使用99/98选择编号0..16383，Data Entry使用6/38。首次需两个selector分量；同kind后续可修改一个分量。跨kind立即停用旧选择并保守等待新完整选择。有效参数改变、跨kind或RPN null清Data Entry缓存及有效性，重复同参不清；无selection的数据不回放。RPN127/127为null，单127不是null，NRPN127/127不当作标准null。清缓存不表示设备参数归零。
- 参数事件的绝对值只是raw14传输组合，不解释具体音源的半音、音分等语义；事件保留coarse/fine及有效性。CC96/97忽略value，仅产生+1/-1增减事件并使绝对拼装状态失效，绝不伪造新的绝对值。
- 增减事件只驱动旋钮步进按键、拖动和勾选“跟随方向”的滚轮；没有绝对值时拒绝范围过滤、`$value`条件、音量/鼠标数值跟随、变量from_value及MIDI数值转发。原始7bit CC映射仍可用，cc/cc14/rpn/nrpn按类型分别匹配。
- CC121仅清当前来源/通道的解析状态，这是应用策略，不模拟完整音源重置。无录制回放或编码自动探测。

### 配置迁移和回滚

EXE使用其旁边的 `config.json`；源码使用项目根目录配置。schema1/2首次升级先按原字节写 `config.json.pre-midi-expansion.bak`，再原子迁移为版本3；schema1另保留 `config.json.pre-keyboards.bak`。已有备份不覆盖。映射ID、顺序、条件、动作和宏延迟均保留；旧弯音及CC level行为保持。

版本3中每份keyboard保存 `input_ports` 精确名称列表，旧单口迁移为单元素列表；空列表表示无输入，不从旧 `input_port` 静默回退。旧字段仅保留首输入兼容视图。缺少关键字段的新版配置或未知未来版本拒绝加载，不覆盖原文件。

回滚时先退出新版，恢复旧版整个发布目录，并将对应旧配置备份复制为 `config.json`。构建脚本会在成功和失败时恢复构建前的用户配置及迁移备份；仍建议升级前备份整个发布文件夹。首轮迁移备份只反映升级时刻，后续编辑请另行备份。

## 进阶实战配置示例

### 示例 1：打造“按住打击垫 = Shift 第二层”（层覆盖）

想让同一个琴键 `C4` 默认按出 `Z`，按住打击垫 1 时按出 `Ctrl + Z`：

1. **映射 A（定义 Shift 键）**：学习打击垫 1 -> 事件选 `按下+松开` -> 动作选 **设置变量**，变量名 `shift`，操作选 `设为输入数值`（按下时力度 > 0，松开时自动归 0）。
2. **映射 B（Shift 层动作，排在前面）**：学习琴键 `C4` -> 条件填入 `shift>0` -> **勾选“命中后不再处理后面的映射”** -> 动作设为按键 `ctrl+z`。
3. **映射 C（默认层动作，排在后面）**：学习琴键 `C4` -> 条件留空 -> 动作设为按键 `z`。

### 示例 2：一个旋钮分饰多角（按下切换功能模式）

1. **模式切换键**：用一个按钮绑定动作 **设置变量** -> 变量名 `knob_mode`，操作 `加上`，值 `1`，下限 `0`，上限 `2`，**勾选“超出范围时循环”**，并开启 **HUD 提示**。每按一次在 `0 -> 1 -> 2 -> 0` 间循环。
2. **模式 0（缩放画布）**：学习旋钮 -> 条件 `knob_mode==0` -> 动作选 **鼠标滚轮**，修饰键 `ctrl`，勾选 `跟随旋钮方向` 与 `旋钮加速`。
3. **模式 1（时间轴移动）**：学习同一旋钮 -> 条件 `knob_mode==1` -> 动作选 **旋钮步进按键**，右转 `right`，左转 `left`，勾选 `旋钮加速`。
4. **模式 2（PS 调画笔大小）**：学习同一旋钮 -> 条件 `knob_mode==2` -> 动作选 **修饰键+拖动（旋钮）**，修饰键 `alt`，拖动键 `右键`，每格 X `4`，停止后松开 `400 ms`。

## 常见问题（FAQ）

- **Q：为什么在某个软件（如游戏或以管理员运行的软件）里按键不生效？**  
  **A**：Windows UIPI（用户界面特权隔离）规定低权限进程无法向管理员进程注入输入。请使用 `.\run.ps1 -Admin` 或右键以管理员身份运行本程序（标题栏会显示 `[管理员]`）。

- **Q：我的旋钮是无限旋转的（相对编码），为什么方向不对？**  
  **A**：观察监视值，在映射编辑窗口选择对应编码和方向反转；不同厂商并无统一相对编码，程序不自动判断。
